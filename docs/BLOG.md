# 我把散热器的小屏幕，改成了能自己写动画的副屏

> 顺手把一个 389 MB 的 Qt 应用换成了 590 KB 的单文件 exe。
> 仓库：[Coolleo Studio](https://github.com/Bronya-Hacker/coolleo-studio)

---

## 起因

我机箱里那个 Coolleo（酷凛）散热器，屏幕上带一块 320×240 的小彩屏，官方软件能显示 CPU 温度、内存占用，还能换几个动画皮肤。

问题有三个：

1. 它占 **389 MB 内存、9 个进程、188 个线程**（Qt + QtWebEngine 全家桶），开机自启后风扇都多转两圈；
2. 皮肤是官方加密的 `.mPanelTheme` 包，我只能在他们给的那几个里挑；
3. 屏幕内容永远是他们设计的样子——我想让它显示什么，得等官方更新。

于是决定从零重写。目标很明确：**屏幕显示什么，由我说了算。**

---

## 一、先把协议拆了

设备是个标准 HID，插上去 Windows 直接认，不用装驱动：

```
VID 0x1600 / PID 0x3006
输出报告 1025 字节 = 1 字节 ReportID + 1024 字节数据
```

一帧画面 = 1 个头包 + N 个数据包。头包里塞了魔数、长度和时间戳：

```
[0]      = 0x00
[1..3]   = "CRT"
[6..8]   = "DRA"
[9..12]  = JPEG 长度 + 32   （大端 u32）
[13]     = 0xB1
[14..21] = 时间戳
[33..]   = JPEG 的前 992 字节
```

后面的数据包就是接着塞 `[1..1024]` 的裸 JPEG 字节。

逆向过程没有想象中难：用 Frida hook `CreateFileW` / `WriteFile` 抓官方软件的写包，拿到原始字节流；再拿 capstone 反汇编那 1025 字节的组装函数，确认头部字段语义；最后用自研代码逐字段回放，屏幕亮了。

**第一个残酷的发现：上限 20 fps。**

不是软件慢，是 HID 中断传输的带宽就这么点。一帧 JPEG 按 8–20 KB 算，20 fps 已经是天花板，再怎么优化代码也突破不了。所以我从一开始就没打算做 60 fps 的丝滑动画——**先把每帧的信息密度做高**。

> 顺带一个优化：静止画面用 16×12 的缩略签名做帧间 diff，差异小于阈值就跳过不推。实测看静态界面时，90 次渲染只发了 3 帧，省了 96% 的带宽。

## 二、界面用什么写

一开始想用 Electron，跟官方一样。装完就放弃了——启动 200 MB 内存，为了一个 320×240 的预览窗口不值。

又试了 WebView2，能嵌进原生窗口，但还是要拖一个几十 MB 的运行时。

最后的方案有点野：**用 C++ 起一个 HTTP 服务，界面就是浏览器里的一个网页。**

```
coolleo-svc.exe         590 KB，托盘常驻
  └─ HTTP 127.0.0.1:8765
       └─ ui/index.html   你浏览器打开它
```

好处立刻显现：

- exe 只有 **590 KB**，零运行时依赖（导入表全是系统 DLL）；
- 界面用 HTML/CSS/JS 写，改配色改布局是分钟级的事；
- 调试就用 DevTools，不用装什么 Qt Inspector；
- 关掉浏览器，托盘里那个进程还在，屏幕照常刷新。

代价是「双击托盘图标打开界面」变成了「打开一个浏览器标签页」。这个我觉得完全能接受——反正浏览器一直开着。

---

## 三、关掉浏览器，屏幕不能黑

第一版架构是「浏览器画好 → POST 给后端 → 后端转发给设备」。写完就发现一个硬伤：

**浏览器一关，屏幕就停在最后一帧不动了。**

这是架构问题，不是 bug。数据采样在 C++ 里，渲染在浏览器里，中间断了一环。

解决办法是把渲染也做进后端：GDI+ 按同一份主题 JSON 再画一遍。于是渲染链路变成有优先级的：

```
网页推帧（浏览器在） > 窗口投送（开了投送） > 后端画主题 > 最后一帧缓存 > 内置仪表盘
```

代价是同一套控件要实现两遍（Canvas 一遍、GDI+ 一遍）。但换来的是：**浏览器只是个编辑器，不是运行时的必需品。**

现在我的日常流程是——想改主题就开浏览器，改完关掉，屏幕继续跑。

---

## 四、主题 = JSON + 表达式

这是这次重写的核心。

官方皮肤是加密二进制包，我的是纯文本：

```json
{
  "name": "我的表盘",
  "canvas": { "width": 320, "height": 240, "fps": 20, "background": "#000000" },
  "widgets": [
    {
      "type": "arcGauge",
      "rect": { "x": 20, "y": 20, "w": 120, "h": 120 },
      "props": { "label": "CPU", "arcColor": "#22d3ee",
                 "thWarn": 70, "thDanger": 90 },
      "bindings": { "value": "cpu.load" }
    },
    {
      "type": "text",
      "rect": { "x": 160, "y": 40, "w": 140, "h": 40 },
      "props": { "template": "${cpu.temp | round(0)}°C",
                 "font": "bold 28px Consolas" },
      "visibleWhen": "cpu.load > 50"
    }
  ]
}
```

几个我比较满意的设计：

**表达式管道。** `bindings` 说「这个属性吃什么数据」，`template` 里可以继续加工：

```
${cpu.temp | round(1)}          → 51.3
${mem.usedGB | clamp(0,32)}GB   → 24.1GB
```

支持 `round / floor / ceil / abs / clamp / min / max / mul / div`，可以串联。

**阈值预警。** 任何数值控件加四个属性就变成会变色的仪表：

```json
{ "thWarn": 70, "thWarnColor": "#f59e0b",
  "thDanger": 90, "thDangerColor": "#ef4444" }
```

温度上 70 变黄，上 90 变红，弧、进度条、文字都吃这套规则。

**条件显隐。** `visibleWhen: "cpu.temp >= 70 && gpu.load < 50"` —— 只在 CPU 发热的时候才把那块警告信息亮出来，平时让位给别的元素。320×240 一共就 76800 个像素，能省一块地方是一块。

**数值平滑。** 采样是离散的，直接把 `cpu.load` 打到指针上会一直抖。加了一层缓动（`cur + (target-cur)*0.22`），指针就像真的仪表一样晃过去。

编辑器本身也做完整了：拖拽缩放、六向对齐、吸附网格、多选批量改属性、撤销重做、复制粘贴、控件锁定/隐藏/成组、主题分类与缩略图、单文件主题包导入导出。

## 五、投一个窗口上去

除了主题，还能把某一个窗口实时投到小屏。

一开始做的是"整屏投送"（DXGI Desktop Duplication，录屏软件用的那套）。真用起来才发现没意义：把 2560×1440 缩到 320×240，字全糊成一团，什么都看不清。所以砍掉了，只留**单个窗口**投送（`PrintWindow`，窗口自己按内容缩放）。

20 fps 上限卡在 HID 带宽上，不是抓屏速度。

现在它的定位很明确：把网易云的小窗、一个计时器、一个监控面板丢上去 —— 单窗口、少信息、远看能认。选过的窗口会被记住，下次启动自动接着投。

## 六、那扇打不开的门

官方主题包里带了动画。我一开始想直接把 mp4 抽出来用，结果撞了墙。

`.mPanelTheme` 其实是个 ZIP，解开里面有 `manifest.json`（控件布局，明文）、几张 PNG（明文），和一个 9 MB 的 `isEncryptionQ0UGPh06jc6C.mp4`。

这个 mp4 看着完全正常：`ftyp` / `free` / `mdat` / `moov` 齐全，长度字段也对。但一解码就报 `non-existing PPS 1 referenced`——**每一位都是密文**，熵 7.95 bits/byte。

后面几天的记录：

- 在官方 exe 里翻到一个 `decryption_key = c7e16c44...`（32 hex = AES-128），拿它把 ECB/CBC/CTR 全试了一遍，各种偏移、逐 NAL payload 都试了，ffmpeg 的错误数一点没降；
- Frida hook `libcrypto-1_1-x64.dll` 的 `AES_set_decrypt_key` / `AES_cbc_encrypt`，官方播这个视频时**一次都没调用**；
- hook `avcodec_send_packet` 抓到 7682 个包、14 MB 数据，喂给 ffmpeg 还是密的；
- hook `avcodec_receive_frame`，**一帧都没有**——解码器根本没吐出画面。

结论：解密发生在官方自己的解码链路里，既不在文件层也不走 OpenSSL。要接着挖就得逆整条渲染管线，投入产出比太低。

所以我放弃了视频解密，改成「自己准备素材」。想放动画？拿个 mp4 或者 GIF 转一下，编辑器里直接导。**能力上不损失什么，只是不能白嫖官方的皮肤。**

这个坑教训是：**先做便宜的验证，再投入贵的逆向。** 我如果在 hook libcrypto 那步就停手，能省两天。

## 七、前后对比

| | 官方 Coolleo_Center_Lite | Coolleo Studio |
|---|---|---|
| 进程 / 线程 | 9 / 188 | **1 / 11** |
| 常驻内存 | 389 MB（私有 657 MB） | **26–30 MB（私有 5–9 MB）** |
| 空闲 CPU | 6.2% | **0.6%** |
| 体积 | ≈180 MB | **590 KB + 一个 html** |
| 主题 | 加密二进制 | **明文 JSON** |
| 加控件 | 改 QML 重编译 | 编辑器里拖一个 |
| 关掉浏览器 | — | **后端继续渲染** |

内存这块中间调了挺久：一开始 63 MB，靠「D3D 懒创建 + 停止抓屏时释放 duplication session + 进程级 GDI+ 单例」压到 30 MB。CPU 那条曲线更离谱，最初一采样就打到 100%——PDH 的 rate counter 被我按 20 fps 去读了，改成 `GetSystemTimes` 自己算差值 + 900ms 节流 + EMA 平滑才正常。

## 八、几个真踩过的坑

**1. mongoose 的 `mg_http_reply` 会把二进制截断。**
加 URL 图片导入时，下载回来的 PNG 永远是 0 字节。因为 `mg_http_reply` 用 `%.*s` 格式化 body，遇到 `\0` 就停。得手写响应头 + `mg_send(c, data, size)`。

**2. 强杀进程会让设备卡在不可写状态。**
用任务管理器结束托盘进程，再启动新实例，`open` 成功但每次写报告都失败——设备停在半截事务上。加了个保险：连续失败 40 次就关掉句柄重开一次，不用拔插 USB。

**3. PowerShell 会吃掉 JS 里的 `$()`。**
我图省事用 `powershell -replace` 打补丁，`$('mediaZoom')` 被吃成裸变量 `mediaZoom`，整个 `<script>` 白屏。此后所有代码修改一律走文件式 Python 脚本 + `node --check`。

**4. 一次正则吃掉了 CSS 的右括号。**
改媒体查询里的一个宽度，`re.sub` 顺手删了 `}`，后面几十条规则跑出 `@media` 变成全局规则，布局全乱。教训：改 CSS 后先校验花括号配平。

**5. `.sel-box .handle` 的 `pointer-events`。**
缩放手柄是叠在 canvas 上的 DOM 元素，`pointer-events:auto` 把点击吃掉了，canvas 的 `pointerdown` 收不到，于是"缩放没反应"。改成 `pointer-events:none` 让事件穿透，命中判定自己算。

## 九、现在的状态

- 协议单测 44/44，端到端 299 帧 / 5579 包 / 0 错误
- 主题编辑器 3 套自动化验收脚本（102 项断言）全绿
- 窗口投送实测 20.0 fps / 0 错误
- 支持 11 类控件、12 个系统指标、表达式 / 阈值 / 条件显隐 / 分组

还没做的：

- **亮度控制**命令未知，接口直接返回不支持（怕把设备写复位）
- CPU/GPU 温度依赖 LibreHardwareMonitor 之类的 WMI 提供者，本程序不读 MSR、不装驱动
- 主题 JSON 还在内存里，重启服务会回到最后一帧

## 最后

这个项目的价值可能不在"省了多少内存"，而在于**那块小屏幕终于变成了我的屏幕**。

以前它显示什么由厂商决定；现在它显示什么由一行 JSON 决定。想加一个"只在编译时出现的折线图"，改两行；想让它变成时钟，删几个控件。

顺手把内存从 389 MB 干到 30 MB，算是附赠。
